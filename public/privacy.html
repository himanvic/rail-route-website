TRUST & TRANSPARENCY

Understand where your data goes. And what stays here.

This page explains how Rail & Route's train-status feature works, what our site is designed to retain, and when another service is involved. We don't offer direct PNR lookup.

Our simple ruleAsk for as little as we need, don't collect ticket details, keep provider credentials off the browser, and label cached information clearly.

A train or route enquiry, step by step.

ILLUSTRATED DATA FLOW
01 / YOUR BROWSER

Choose a train

You can enter a train number, search for station suggestions, or choose source and destination stations plus a date. Those enquiry fields go to our own API endpoint.

02 / CLOUDFLARE

Protect the request

The server-side function validates the input and uses a private API secret. Station suggestions, static between-station timetables and train schedules may be served from short-lived edge caches.

03 / DATA PROVIDER

Return status

If configured, the external provider returns live running status or scheduled route information. The site shows the supplied data and when our server retrieved it.

PNR is intentionally different: no PNR field, no ticket details and no PNR API request on this website.

WHAT WE KEEP

Minimal by default.

The first version has no account system and no central database of user searches. For a fallback, the browser may keep one most-recent successful train-status response in local storage on your device. The server can also briefly cache train-status responses at Cloudflare's edge to avoid repeating API calls.

Those caches are not a passenger profile or PNR record. The Journey Explorer keeps the latest journey result only in page memory for failure fallback; the site does not create a central user search-history database. Station suggestions are cached in page memory while you use the page. Clear this site's local storage in your browser to remove the device-local train-status copy.

WHAT WE DON'T ASK FOR

No ticket details here.

This website does not ask you to enter your PNR, passenger name, ticket number, phone number or account credentials. The PNR action opens the official enquiry site separately. If you use Journey Explorer, the station search term, chosen station codes and journey date may be sent to the configured train-data provider to fulfil the search.

Once you leave for another service, that service's own privacy practices apply. We cannot control how an external website handles the information entered there.

THIRD-PARTY SERVICES

Live status has a provider.

Live train status is supplied by an external data provider when a valid provider credential has been configured. The current starter includes an optional RailRadar adapter. The provider may receive the train number, journey date and technical request metadata needed to answer the lookup.

Cloudflare also processes requests as the hosting and API platform. Their systems may process technical and security logs under their own terms. This site does not promise that no technical data is ever logged by infrastructure providers.

Before using a provider publicly, review its current terms, free-tier limits, caching permissions and privacy policy.

ACCURACY & LIMITATIONS

We won't invent a live result.

Train-status information can be delayed, incomplete or unavailable. When a live request fails, the site may show a previously successful train status with its actual retrieval timestamp and a clear cached/stale label. Journey Explorer uses scheduled timetable data and can show a previous in-session search if the latest request fails. The moving train icon on the route line is decorative and does not represent live GPS position. If no cached result exists, the site displays an error instead.

The site is an independent student project and is not affiliated with Indian Railways, IRCTC, CRIS or NTES. Availability depends on our host and the external provider. Free services can change, pause, limit or discontinue access.

Provider policy note

The provider's free sandbox terms and quotas can change and may limit usage to personal, non-commercial testing. We will not represent access as production-approved until the current provider terms have been checked. No paid upgrade should be enabled without the project owner's approval.
